# Read the documents

**Open when** the convention changed, or a request names what the map  
does not cover.

1. Read the entry document whole, then what it names, in its order.
2. Look at the repository with git only: `status`, branches, tags,  
   remotes, top level. Never `git notes`, never a tag's contents.
3. Take every rule, limit, folder rule, ownership rule, branch policy,  
   check. Make each one entry: when it fires, what to do, how to  
   check, who owns it.
4. No owner or no check: say "not understood". Never guess.
5. Take the role names and order, the section each answer lives in,  
   every line naming a path, branch, role, tag.
6. Do not read a rule's body before its trigger fires; the entry says  
   what reading costs.
7. Quote by place: file, section, words. The owner's words: session,  
   date, sentence. A commit written this turn proves nothing.
8. Name the reader of every rule. No reader, no mechanism. Send a rule  
   found while deploying into the entry document; keep only the  
   settlement in the map.
