# TBD-Roots — the method

**Reading starts nothing.** Let the owner name the work; treat the  
prompts as what is available, not a queue that starts itself.

Treat the repository's history as the product: every commit is an  
assertion, and read the tree as knowledge, not as a log. Take the  
method as a package of prompts — one per moment — and let the map, in  
the harness, say which one fires.

**How a run starts.** Default: **the run does the work.** Let the  
owner name it; open the map, write the mechanism, land the commit,  
push. Announce no plan; ask no permission.

Let the word change the mode only:

- **«dry run»** — survey and report; no act, no commit, no push.
- **«questions»** — the questionnaire's unanswered questions only.
- **«plan»** — the entry and the todo written; commit nothing.
- **«re-read»** — re-read the convention and the map; report the  
  delta.

**The law.** Read [`write history`](<TBD-ROOTS - write history.md>) as  
the full text; the run that writes history reads it. Read  
[`the law one line each`](<TBD-ROOTS - the law one line each.md>) as  
the dumb list in this folder: one line per rule, to recognise a rule  
fast.

**In one breath.** Keep one word, one meaning. Treat tokens as the  
budget. Turn a sequence typed twice into a script. Restate no file in  
another: a rule lives in one file; a prompt names the file and the  
moment. Treat a clarification as spec work: write it into the file of  
that kind of fact, in the same turn.

Read the article as its author wrote it; where it and the law differ,  
the law decides the act.

*The same thing, named twice:* *architectural conclusion* — an  
assertion; *version* — an edition; *discovery order in, explanation  
order out* — chronology is the input, never the output; *developer  
rebase* and *editorial rebase* — the two rebases; *editor*, *team  
lead* — the owner; *the trunk is pruned* — the pass lays the trunk  
into the roots; *entry point* — the same word.

*Four places a careful reader reads wrong:*

- a team lead or an editor performs the editorial pass → **the pass is  
  the owner's**, by his word;
- the visible trunk is pruned and reorganised → the pass **lays the  
  trunk into the roots**; the trunk receives merges and assembles  
  nothing;
- follow the branch sequence chronologically → ordered **iteration,  
  then role, then committer time**; chronology is the input, never the  
  output; branch names are the owner's, not a reading list;
- fixups, experiments, failed attempts are the material a developer's  
  rebase tidies → a **`fixup!` is a finished correction**, never a  
  draft; the draft is work not yet committed.
