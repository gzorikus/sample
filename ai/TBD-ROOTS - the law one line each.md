# The law, one line each

**The dumb list in this folder.** One line per rule; the number is its  
rule in [`write history`](<TBD-ROOTS - write history.md>). Read the  
law by the run that writes history; read this list to recognise a rule  
fast.

1. Write the body as why the commit exists: the prehistory, never the  
   mechanics.
2. Give a `fixup!` the same why, and open its body with a one-line  
   heading — that line becomes the todo comment.
3. Give a merge the standard git text and no body.
4. Keep subjects unique within an edition; where the act recurs, write  
   a `fixup!`, not a new subject.
5. Target the **subject** of a `fixup`, never a line, a file or a  
   hash; never a numbered commit of its own branch; never a merge;  
   never a loose edit; keep one fixup per essence, folded in, not  
   duplicated.
6. Use three branch classes only: trunk, entry-point (bare,  
   unprefixed), `PR/`.
7. Start a `PR/` branch at the trunk's head, keep it only with its PR,  
   and birth it on every change request, a follow-up included; where a  
   branch already refines it — stop and delegate to that run. Rebase  
   it on every advance, no reminder; a meaning conflict — stop, name  
   both sides, ask.
8. Require a `wip-full-solution` beside every `wip-` branch.
9. Merge only where the knowledge depends on several pieces; make an  
   octopus vertical compression.
10. Let the trunk receive; assemble nothing on it. Make the merge the  
    stump; count numbers split at it.
11. Rebuild the whole tree at the second rebase; give one flat tag per  
    branch per iteration.
12. Number every commit that reaches the tree `{N}|{role}: {subject}`.
13. Place placeholders in advance, by a `fixup`.
14. Never treat a placeholder as an invariant.
15. Rebuild the whole tree each iteration: a fresh commit per branch.
16. Keep all iterations in one todo file; read the current iteration  
    and its goal there.
17. Ask the todo's path once; it need not be inside the repository.
18. Create a PR with its branch, never closed and re-created; names  
    are the owner's.
19. Measure a message, never eyeball it: subject ≤50, body lines ≤70  
    plus two spaces — the wrap law and its algorithm are  
    [`wrap a text`].
20. Never name in a commit what stands above it.
21. Push a branch and open its PR on the request that names the work.
22. Send a request no rule covers into the trunk.
23. Do nothing without the owner's word or a duty the convention gives  
    a role.
24. Read the root as the project's truth: read `init` and every  
    standing `fixup!` on it first.
25. Correct with a `fixup!` on exactly one commit; add no section: a  
    heading or a block that would stand alone is new knowledge and  
    needs a word; keep it inside one role's folder.
26. Give a fixup no subject, iteration or role of its own: they come  
    from its target. 26a. Rename a statement with an `amend!` at a  
    commit the branch does not carry — only on the owner's word, and  
    only with no `PR/` branch open at the rebase.
27. Treat deleting another's text as new knowledge; it needs a word.
28. Write no new knowledge without his word — new is any commit that  
    is not a `fixup!`/`amend!`/`squash!`; a merge is never the run's.
29. Write one rule, one line — addressable by the slug of its first  
    line.
30. Keep one home per fact: the convention, this law, or an artefact —  
    never two.
31. Name no harness in a rule.
32. Never delete an error the owner names: its content finds its home.
33. Never imply a rebase by a landing: the developer's keeps its own  
    branch clean; the editorial pass is the owner's and re-cuts the  
    tree.
34. Read a convention line as the project's answer or a restatement of  
    this law — remove a restatement.
35. Write a rule on a failure, not a remark: read the rule before the  
    work, keep the remark behind the entry.
36. Give every area a route — the order a change in it is made —  
    written once and corrected in the commit that corrects it.
37. Read the convention as what must be; the history as what was —  
    where they disagree, the history is right.
38. Write every rule as an order a run can execute without deciding:  
    what to do, the test, the boundary, the defect.
39. Work each branch in its own worktree beside the clone; a checkout  
    never switches branches.
40. Script every action: no act by hand, the map's `mechanisms` name  
    it, hash and all; `code` is the only default; a run needs no  
    model.
41. Record every new word the owner speaks: fix its meaning in his  
    words, add it to the vocabulary of its kind, land it as a  
    `fixup!`; expand the language only as far as the work needs.
42. Merge fast-forward only; delete the branch and its worktrees in  
    the same act; the owner's merge word carries the deletion; leave  
    neither standing, reuse no name unless the repository says  
    otherwise.
